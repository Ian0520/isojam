# Reproducible CPU API environment

This workflow targets CPython 3.12 on Linux x86_64. It prepares the API without
BS-RoFormer, PyTorch, CUDA libraries, or model weights. Set
`ISOJAM_PROCESSING_MODE=disabled`; new processing jobs return 503 until a worker
is connected. The GPU inference environment is a separate, future deployment
artifact and is not covered by these locks.

## Dependency files

- `backend/pyproject.toml` declares direct dependencies and supported ranges.
- `backend/requirements-api.txt` pins the API's direct and transitive Python
  dependencies, including the project's build requirements.
- `backend/requirements-dev.txt` adds the `dev` extra, constrained to the same
  versions as the API lock wherever packages overlap.

Both requirements files are generated by pip-tools and committed. Each package
has an exact version and SHA-256 hashes of acceptable release files. Do not edit
individual generated entries by hand. Hashes verify package bytes against the
lock; they do not establish that a package is trustworthy or free of bugs.

These files do not lock Python itself, the operating system, or native system
libraries. SoundFile still uses libsndfile, supplied by a supported binary wheel
or the operating system. A container will define those additional runtime choices.
Regenerate and test locks for another Python version, operating system, or CPU
architecture rather than assuming this environment's resolution applies there.

## Install the API

From `backend`, create a fresh environment rather than modifying an existing GPU
environment:

```bash
python3.12 -m venv /tmp/isojam-api
source /tmp/isojam-api/bin/activate
python -m pip install pip==26.2.1
python -m pip install --require-hashes --only-binary=:all: -r requirements-api.txt
python -m pip install --no-deps --no-build-isolation .
python -m pip check
```

The hashed install supplies all dependencies and build tools first.
`--only-binary=:all:` rejects packages without compatible wheels instead of
building them with unrecorded system tools. The project install then builds the
local source using those installed build requirements. `--no-deps` prevents
another dependency resolution; `--no-build-isolation` prevents pip from creating
a separate build environment with newly selected build packages. The project
source comes from the checked-out Git revision; it is not hashed by the package
requirements file. The initial pip bootstrap is version-pinned separately.

Configure persistent paths and authentication as described in the README, set
disabled processing, migrate, and start the server:

```bash
export ISOJAM_PROCESSING_MODE=disabled
# Also set ISOJAM_JWT_SECRET_KEY, ISOJAM_DATABASE_PATH, and ISOJAM_AUDIO_STORAGE_DIR.
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Use absolute storage/database paths. For a validation run, use newly created
temporary paths so migration and upload checks cannot touch personal data.

## Install and run tests with the same versions

In the fresh API environment, from `backend`:

```bash
python -m pip install --require-hashes --only-binary=:all: -r requirements-dev.txt
python -m pip check
python -m pytest -q
python -m ruff check app tests scripts migrations/env.py
python -m ruff format --check app tests scripts migrations/env.py
```

The suite uses fake model sessions; it can run without the inference extra.
Subprocess tests exercise migrations, restarted database access, configured audio
storage, and API startup with inference imports blocked. Passing them verifies
API behavior and orchestration, not real model output or CUDA compatibility.

## Regenerate or deliberately update the locks

Use a separate tooling environment with the target Python version. From
`backend`:

```bash
python3.12 -m venv /tmp/isojam-lock-tools
source /tmp/isojam-lock-tools/bin/activate
python -m pip install pip==26.2.1 pip-tools==7.6.1
python scripts/compile_requirements.py
```

The API file is generated first because it constrains the development file.
The build-dependency flags include the backend's build requirements; the
`inference` extra is deliberately not selected. Index configuration is not
embedded in committed files. The generator belongs to the tooling environment;
it is not needed to install or run the API.

The generator checks Python/platform and tooling versions, invokes pip-tools for
the API first and then the development dependencies, and records its own command
in each generated header. Run it after editing `pyproject.toml`. It prefers
compatible versions already in the output files. To deliberately resolve newer
versions across both files:

```bash
python scripts/compile_requirements.py --upgrade
```

Review this as a dependency update; it can change multiple packages. Version pins
are a reproducibility tool, not a reason to stop maintaining dependencies.

After changing direct requirements or updating a lock, review the generated diff,
install into a new environment, run `pip check`, the full suite, and a runtime
smoke check before committing. A resolver finding compatible version ranges is
only the starting point; the application tests establish whether that resolved
combination works for IsoJam.

## Validation recorded on 2026-10-01

A fresh CPython 3.12.3 environment in Ubuntu/WSL installed all 30 API pins with
hash checking and binary wheels, then built and installed IsoJam without another
dependency or build-tool resolution. `pip check` passed. Before installing test
tools, a real Uvicorn process served health, registration, login, and WAV upload,
rejected a processing job with 503 without inserting a job row, and retained the
registered account after a server restart. Alembic migrated a disposable database;
audio and metadata were confined to temporary paths. No model or test packages
were installed for that smoke check.

After installing the development lock (39 pins in total), all 266 tests passed;
Ruff lint and formatting checks passed across the application, tests, generator,
and migration environment. Shared lock entries matched installed versions, both
locks excluded inference packages, and a repeated generation from another
working directory produced identical files. Missing tooling was rejected without
changing the locks. This does not yet validate a container or real GPU processing.
